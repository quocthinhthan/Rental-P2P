# RentHub web screen inventory

This inventory covers the 28 route entries in the web application, including separate create/edit routes for the shared listing form and the fallback route. Embedded interactions and global navigation follow the route inventory. Routes and states are verified in source. Current responsive behavior is based on component markup and CSS. The responsive requirements describe behavior for the redesign, without prescribing layouts or breakpoints. [Web route definitions](../../frontend/src/App.jsx)

## Visual exploration priorities

| Priority | Representative surfaces | What they establish |
| --- | --- | --- |
| First board previews | **Home, Shop, Item detail and Rental detail** | Brand and discovery, dense results and filters, the price/availability/trust decision, and the operational side of a rental. Use the same four previews on all three boards. |
| Shared component samples | **Rental management**, **pickup/return review**, **status and trust badges**, **login/eKYC prompt**, **payment result** | Role switching, evidence, forms, waiting/failure states, and readability at mobile widths. Apply the visual system without producing full screens for every sample. |
| Later coverage | Listing create/edit, account, public profile, favorites, finance, support and admin | Extend the selected direction to account setup, management and high-density operations after Founder selection. |

## Responsive baseline and criteria for the boards

- The header swaps to mobile navigation below the desktop layout. Shop places filters in a sidebar on large screens and exposes a filter toggler on smaller screens. Listing detail drops the sticky gallery and uses horizontal thumbnail and tab scrolling. [Layout CSS](../../frontend/src/styles/layout.css) · [Shop CSS](../../frontend/src/styles/ShopPage.css) · [Item detail CSS](../../frontend/src/styles/ItemDetailPage.css)
- Rental detail moves from columns to a single column around 1024 px and its timeline becomes one column at 640 px. Several admin/finance tables scroll horizontally. Use this as evidence of current behavior. Choose new layouts based on task order, readable labels, and evidence density. [Rental detail CSS](../../frontend/src/styles/RentalDetailPage.css) · [Admin table CSS](../../frontend/src/styles/AdminProductManagement.css) · [Finance CSS](../../frontend/src/styles/FinancialDashboardPage.css)
- Show desktop and narrow phone views around 1440 px and 390 px on the comparison boards. The widths are design samples. Check a narrower viewport during implementation planning. Use readable contrast, text labels in addition to color, visible focus, appropriately sized touch targets, and controls that work without hover. Plan for long Vietnamese strings, missing photos, currency formatting and mobile keyboard overlap.
